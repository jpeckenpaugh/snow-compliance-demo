Purpose

What this project delivers

This is the recommendation and design package for a demonstrable Snowflake capability in a legal-services context. It is deliberately scoped to be built and shown quickly, while exercising the Snowflake features that matter to a compliance audience: governed access, data protection, and auditability.

Everything here is a starting point for discussion. The board is asked to confirm scope, the data-sourcing approach, and the security posture before we build.

Outcomes

Four things the demo proves

1. Governed ingestion

Real contract text and CUAD clause annotations are loaded and joined to synthetic clients, matters, and staff with validated foreign-key relationships.

2. Matter-level confidentiality

Attorneys see only the matters they are authorized for. Snowflake row access policies and masking enforce the wall at query time, not in application code.

3. Contract-risk analytics

CUAD clause categories feed a transparent, rule-based risk rubric that flags termination, indemnification, liability, and governing-law exposure.

4. Verifiable audit

We run the same query under multiple roles, capture allowed and denied access, and reconstruct it from Snowflake's own query and access history.

Rationale

Why CUAD plus synthetic records

Fabricated clause text produces a demo that feels fake and can misrepresent the strength of the platform. The Contract Understanding Atticus Dataset gives us 510 real commercial contracts with 41 expert-annotated clause categories — genuine language and genuine labels.

CUAD is public research data released under CC BY 4.0. We attach fictional matters and confidentiality labels strictly to demonstrate the mechanics. We will never present these documents as genuinely privileged, and we will carry the license attribution wherever the data appears.

Non-negotiable framing Public documents, fictional matters, and a simulated legal-review rubric. The demo must not imply real legal advice, real privilege, or real client confidentiality.

Recommendations

Ten recommendations

  1. Use CUAD as the factual spine. 20–30 contracts for the demo core, with the option to scale to all 510.
  2. Synthesize the business layer, not the legal text. Faker generates clients, matters, staff, assignments, and approvals.
  3. Model matters as the confidentiality boundary. Every access decision keys off matter_id.
  4. Enforce with row access policies on a mapping table. No matter-based filtering in application SQL.
  5. Centralize policy in a SECURITY schema owned by a compliance role, applied consistently across tables.
  6. Mask sensitive metadata by role (client PII, deal values) with dynamic data masking and classification tags.
  7. Keep the risk rubric transparent and editable. Rules live as data in a reference table, so thresholds are reviewable — and clearly labeled simulated.
  8. Prove governance through Snowflake's own logs. Query history, access history, and policy references are the evidence.
  9. Ship the review site from this repo. GitHub Pages from main is the board's staging surface.
  10. Keep costs near zero. X-Small warehouses with aggressive auto-suspend, and a small data footprint.
