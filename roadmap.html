Schedule

Phased delivery

  1. Enablement · Platform

    Snowflake demo account, database/role DDL, secrets wired, this review site live on main.

  2. Ingest & organize · Prototype

    CUAD loader, Faker generator, CORE model, data-quality assertions. Accept: all FK checks pass.

  3. Confidentiality · Platform + Prototype

    Roles, mapping table, row access policy on every matter_id table, masking. Accept: cross-matter query returns 0 rows.

  4. Risk analytics · Prototype

    Risk-rule table, scoring view, high-risk register. Accept: bands render for loaded contracts.

  5. Verify & audit · Platform

    Multi-role test run, query-history evidence capture, GOV views. Accept: evidence pack produced.

  6. Review · CEO + Design

    Publish refreshed site, walk the demo, collect board decisions.

Demo

Board demo script (~4 minutes)

  1. Frame. "Public contract data, fictional matters, simulated review criteria. What we're showing is governance, not legal advice."
  2. Show the data. A CUAD contract, its annotated clauses, and the fictional matter it belongs to.
  3. Log in as ATTORNEY_A. Run the matter query — see authorized matters. Query the other matter — zero rows. Show masked client email.
  4. Switch to ATTORNEY_B. Same query, complementary result. The wall holds at query time.
  5. Risk analytics. Show the high-risk register and the rubric behind the score.
  6. Audit. Open query history for both roles; show the policy attached via POLICY_REFERENCES.
  7. Ask. Confirm scope, data sourcing, account, and rubric framing.
Done

Definition of done

  • Site published at jpeckenpaugh.github.io/snow-compliance-demo.
  • Snowflake demo rebuildable end-to-end from sql/ + ingest/.
  • Cross-matter access denied and demonstrated for at least two attorney roles.
  • Audit evidence captured and linked from the audit page.
  • High-risk-by-matter report produced.
