Recommendation

Proceed in three gated phases, all inside Snowflake

The repository already contains the hard parts (DDL, access model, risk rubric, offline POC). What changes for the full dataset is scale and the requirement that the walkthrough be runnable by hand in Snowsight. The board approved the full-dataset scope and methodology on 2026-10-16.

  1. Parse & normalize inside Snowflake. Load the CUAD JSON into a VARIANT table, then flatten it with LATERAL FLATTEN in SQL. No external pipeline, no API.
  2. Generate simulated RBAC + risk metadata at scale. One matter per contract (510), SQL-generated synthetic layer, role buckets + matter_access_map, row access policy, masking, and the 9-rule simulated rubric.
  3. Web app on Streamlit in Snowflake. It runs as the caller's role, so RBAC + row access policies apply with no separate login store. External portal (with External OAuth) is a later step.

Phase 1

Parse & normalize the full CUAD dataset

Snowflake caps a single VARIANT value at ~16 MB, and the master file is ~40 MB, so it is split into one document per line (NDJSON) for transport only — all parsing and normalization runs in SQL. The runbook has the copy-paste steps.

-- 1. stage the NDJSON and land it (one document per row)
COPY INTO RAW.raw_cuad_json (src, source_file)
FROM (SELECT $1, METADATA$FILENAME FROM @RAW.cuad_stage)
FILE_FORMAT = RAW.json_ff PATTERN = '.*cuad_docs.*';

-- 2. normalize in SQL with LATERAL FLATTEN
CREATE OR REPLACE TABLE RAW.raw_cuad_contracts AS
SELECT 'CUAD-' || LPAD(src:ord::string, 4, '0') AS contract_id,
       src:title::string                        AS contract_name,
       UPPER(TRIM(SPLIT_PART(src:title::string,'-',-1))) AS contract_type,
       src:paragraphs[0]:context::string        AS contract_text
FROM RAW.raw_cuad_json;
Data-quality gates 510 contracts · 20,910 annotations · 6,702 present · 41 categories · 0 orphaned clauses. All measured against the real CUADv1.json.

Assets: ingest/split_cuad_json.py (NDJSON split), sql/full_dataset/06_full_dataset.sql (consolidated DDL), and docs/SNOWFLAKE_WALKTHROUGH.md (the manual runbook).

Phase 2

Simulated RBAC + risk metadata

One matter per contract (510 matters). Everything synthetic is prefixed SYNTHETIC and generated deterministically in SQL — no external generator required.
